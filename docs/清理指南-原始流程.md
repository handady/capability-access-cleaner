# CapabilityAccessManager.db-wal 异常占用清理指南（原始人工流程）

> 本文件是人工流程的存档；`cleanup.ps1` 是它的脚本化实现。

## 问题描述

使用 WizTree 扫描 C 盘时，发现以下路径下的 `.db-wal` 文件异常占用数十 GB 空间：

```
C:\ProgramData\Microsoft\Windows\CapabilityAccessManager\CapabilityAccessManager.db-wal
```

该文件是 Windows **功能访问管理器服务（camsvc）** 的 SQLite WAL（Write-Ahead Log）预写日志，
记录应用访问摄像头、麦克风、位置等隐私权限的事务。正常情况下文件很小（几 KB），
若系统长时间未重启或服务异常，日志会持续累积至数十 GB。

---

## 第一步：发现问题（使用 WizTree）

1. 下载并安装 WizTree（免费磁盘空间分析工具）：https://www.diskanalyzer.com/
2. 打开 WizTree，选择 `C:` 盘，点击**扫描**
3. 扫描完成后，在文件树中展开：
   `Windows → ProgramData → Microsoft → Windows → CapabilityAccessManager`
4. 若 `CapabilityAccessManager.db-wal` 文件体积超过 1 GB，即为异常，需清理

## 第二步：以管理员身份打开 PowerShell

> **重要**：必须是真正的管理员模式，普通窗口无效。

1. 按 `Win` 键，搜索 **"PowerShell"**
2. 右键点击 **Windows PowerShell**，选择 **"以管理员身份运行"**
3. 确认窗口标题栏显示 **"管理员: Windows PowerShell"**（不是普通用户标题）

## 第三步：对目录赋予管理员完全控制权限

```powershell
# 接管目录所有权（递归）
takeown /f "C:\ProgramData\Microsoft\Windows\CapabilityAccessManager" /A /R /D Y

# 赋予 Administrators 完全控制（递归）
icacls "C:\ProgramData\Microsoft\Windows\CapabilityAccessManager" /grant Administrators:F /T
```

预期输出：已成功处理 7 个文件；处理 0 个文件时失败

## 第四步：停止 camsvc 服务

> 注意：服务真实名称是 `camsvc`（功能访问管理器服务），**不是** `CapabilityAccessManager`。

```powershell
Stop-Service -Name "camsvc" -Force
```

无报错即表示停止成功。

## 第五步：截断文件（清空内容，释放空间）

```powershell
$stream = [System.IO.File]::Open(
    "C:\ProgramData\Microsoft\Windows\CapabilityAccessManager\CapabilityAccessManager.db-wal",
    [System.IO.FileMode]::Truncate
)
$stream.Close()
Write-Host "成功！文件已清空。"
```

> ⚠️ **不要直接删除该文件**，截断（清空内容保留文件）是安全做法，
> 直接删除会导致 SQLite 数据库损坏，影响 Windows 应用权限功能。

## 第六步：重启服务

```powershell
Start-Service -Name "camsvc"
```

## 第七步：验证结果

```powershell
Get-Item "C:\ProgramData\Microsoft\Windows\CapabilityAccessManager\CapabilityAccessManager.db-wal" `
  | Select-Object Name, @{N='大小(KB)';E={[math]::Round($_.Length/1KB,2)}}
```

文件大小应接近 `0 KB`，表示清理成功。同时刷新 WizTree 重新扫描 C 盘，确认空间已释放。

---

## 常见问题

| 问题 | 原因 | 解决方式 |
|------|------|----------|
| `icacls` 提示"拒绝访问" | PowerShell 未以管理员身份运行 | 确认标题栏显示"管理员: Windows PowerShell" |
| `Stop-Service` 找不到服务名 | 服务名拼写错误 | 正确服务名为 `camsvc` |
| 截断后文件又快速变大 | 服务重启后日志继续写入 | 属正常现象，日常重启电脑可预防积累 |
| 文件截断后空间未释放 | 文件系统缓存未刷新 | 重启电脑后刷新 WizTree |

## 预防建议

- **定期重启电脑**：Windows 正常关机时，`camsvc` 会自动执行 WAL checkpoint
  （将日志合并回主数据库并清空 wal 文件）
- 若 C 盘空间突然减少，优先用 WizTree 检查此路径

## 完整命令汇总（一键执行，需管理员 PowerShell）

```powershell
# 1. 赋权
takeown /f "C:\ProgramData\Microsoft\Windows\CapabilityAccessManager" /A /R /D Y
icacls "C:\ProgramData\Microsoft\Windows\CapabilityAccessManager" /grant Administrators:F /T

# 2. 停止服务
Stop-Service -Name "camsvc" -Force

# 3. 截断文件
$stream = [System.IO.File]::Open("C:\ProgramData\Microsoft\Windows\CapabilityAccessManager\CapabilityAccessManager.db-wal", [System.IO.FileMode]::Truncate)
$stream.Close()
Write-Host "WAL 文件已清空！"

# 4. 重启服务
Start-Service -Name "camsvc"

# 5. 验证
Get-Item "C:\ProgramData\Microsoft\Windows\CapabilityAccessManager\CapabilityAccessManager.db-wal" | Select-Object Name, @{N='大小(KB)';E={[math]::Round($_.Length/1KB,2)}}
```
